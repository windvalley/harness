# 交接视图与证据化澄清验收

## 合并前验收

- `harness status --handoff --branch <任务分支>` 通过真实 CLI 输出 Markdown 交接视图，包含分支与主分支完整提交、交付方式、Worktree 与未提交改动、方案文件、有效实施授权原话、验收清单、现有验证与评审证据、相关上报、下一步命令及恢复入口。
- 交接视图只读取并整理现有记录，不运行验证或评审，不创建新的状态真源，不改变普通 `status` 的输出和退出语义。
- 分支尚未检出、尚未授权、没有验收清单、已经合入或仍有阻塞时，交接视图如实标明，不伪造已完成事项。
- 上报、授权和验收正文中的常见凭据形式在交接输出中脱敏。
- `status --handoff` 与 `status --post-merge` 同时使用会被拒绝，`status --help` 和命令速查包含新参数。
- 项目规则明确要求先查需求、契约、代码和可用工具；有明确契约支撑的技术实现、兼容性和失败处理取舍由 Agent 记录依据后继续，只有无法自行获得且影响结果的关键信息才询问。
- 产品语义、权限边界、实施授权、危险操作及外部副作用仍须遵循原有确认与授权要求，不能借证据化判断扩大权限。

## 合并后验收

- 无。
