# 核心授权契约

## 目标与主要方案

- 授权后，Agent 可在核心契约范围内自主修订验收清单与方案，不停下等人确认；交付时由 harness 机械生成修订摘要，用户在汇报中查看。
- 新任务记录实施授权必须有核心契约；旧记录保持整份验收清单绑定。

## 验收底线

- 必须发生：契约任务的清单与方案修订不使授权失效；修订摘要出现在 status、交接视图、merge 输出与 PR/MR 描述；评审拿到契约与修订条目。
- 绝对不能发生：没有契约的新授权；Agent 自行确认契约变化；旧记录语义改变；摘要遗漏清单条目变化或在无法还原时谎报没有修订；凭据外泄。
- 失败时：基线无法还原或摘要出错时如实说明，不影响授权判定与交付。

## 必需证据

- `npm test` 与 `npm run docs:check` 全部通过。

## 授权范围

- 允许调整的实现路径：摘要的计算位置与输出格式、测试夹具的改造方式、规则与文档的具体措辞。
- 不允许扩大的操作：不新增依赖与子命令，不改变阶段文件绑定，不迁移旧记录，不发版。
