# 行为说明

- 用户需求：实施此前评审确定的两个 P2 优化。
- 实施方案：同目录的 plan.md。

## 问题

- 当前 `harness status` 面向交付门禁汇总，但跨会话接手时仍需自行拼装验收、授权、证据、上报、未提交改动和恢复入口。
- 当前澄清规则对行为、权限、兼容性和失败语义倾向于要求用户确认，即使仓库已有明确契约，也可能产生不必要的等待。

## 目标行为

- 增加 `harness status --handoff`，按当前真实状态生成可粘贴的 Markdown 交接视图，所有事实来自已有 Git、Worktree 和签名记录。
- 交接视图与门禁结论一致，缺证据或授权失效时不把历史记录写成当前有效事实。
- 有明确需求、接口契约、兼容性要求或测试支撑时，Agent 自主处理技术实现、兼容性和失败处理取舍并记录依据。
- 只有查证后仍缺少无法自行获取、且会影响结果的关键信息时才询问用户。

## 失败时

- 分支或记录缺失时保留已有 `status` 错误与阻塞信息，交接视图仍明确显示未知项和恢复入口。
- 参数组合无效时退出码为 2，不读取或修改业务文件。
- 交接输出不声称记录之外的副作用不存在，统一标明需要接手者核对实际环境。

## 这次不做

- 不新增 `change-record.yaml`、交接文件或另一套持久化状态。
- 不自动执行下一步验证、评审、合并、推送或环境恢复。
- 不放宽产品语义、权限模型、方案实施授权、危险操作和门禁改动确认。
- 不实现 P0/P1 的遗留补测执行器与逐用例 reporter。
