# 验证阻塞处理验收

## 范围

依据已确认的优化建议完善通用验证结果、阻塞上报与外部证据复用。
保持项目普通命令接口、现有 gate、extended 和 observe 的默认交付语义。
UI 台账、浏览器框架、项目目录和测试目标选择继续由项目维护。
本次不增加外部强制检查 schema、依赖图推断、自动基线修复或缓存系统。

## 验收清单

- 验证入口受阻时，规则要求先确认必要验收、失败阶段和合法等价入口。
- 声称存量问题必须有可比证据，不默认运行全量基线，也不绕过必需 gate。
- 普通非零退出只记录命令失败，不从输出猜测断言失败、存量问题或环境故障。
- 缺工具、启动异常、超时、信号终止、缺依赖与配置错误有结构化原因。
- fail-fast 后续检查和前置检查阻塞的测试证据完整记录为未运行，并关联阻塞检查。
- 不适用的测试证据保持不进入执行计划与结果，避免引入额外交付义务。
- observe 保留实际失败原因并独立声明不阻断，失败结果不能当作成功结果复用。
- TDD 还原实现后的已知执行阻塞不能充当有效红灯。
- 技术消除通过 resolve 记录非空原因与证据引用，保留原始上报，不伪造人工答复。
- resolve 不填补验证与评审证据，失败 gate 继续拒绝交付。
- 上报自动绑定实际分支提交，不依赖时间先后，不采信调用方提供的 HEAD。
- 上报绑定当前待验收义务集合，新增义务不能沿用旧上报放行。
- 删除任务分支后仍可对待验收义务上报，验签异常不被解释为验收完成。
- 合并时受主分支变化影响的外部证据重新核对，过期后列为未执行。
- 不受影响的 gate 和外部证据继续复用，extended 过期不自动升级为硬门禁。
- 状态页与收尾提示按已知原因提供下一步，环境修复不一律要求修改业务代码或提交。
- 文档站从真实内容源生成，并通过生成一致性检查。

## 验证方式

集成测试通过隔离 Git 仓库运行真实 harness CLI、验证命令、Stop 钩子和模拟合并结果。
验证命令使用普通 Node 进程，不依赖特定前端框架或项目业务台账。
新增测试覆盖 `test/verification-outcomes.test.mjs`、`test/escalation.test.mjs`，并扩展合并、外部证据和收尾检查的既有回归。
各行为先新增测试确认旧实现失败，再实现并运行相应回归。
最终运行 `npm test`、`npm run docs:check` 和 `git diff --check`。
