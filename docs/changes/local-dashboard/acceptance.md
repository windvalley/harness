# 本机跨项目只读 Dashboard 验收

## 范围

本清单对应 `docs/changes/local-dashboard/plan.md` 的完整能力设计。
本次文档任务只确认设计、边界、实施阶段和未来验收要求，不代表下列功能已经实现。
功能实施按阶段另行授权和交付，未完成项目不得标记为已完成。

## 一、范围与语义

- 页面只覆盖当前用户已登记项目，明确提示未登记项目不在统计范围内。
- 不默认扫描整个用户目录，已有项目可以通过显式入口纳入。
- 同一 Git common dir 下的多个 Worktree 只统计和展示为一个项目。
- 流程活动、全部工具调用、客户端会话时长是不同概念，首版只承诺流程活动统计。
- `merge`、`submit.ready` 和 `sync` 分开命名和计数，不把 PR/MR 就绪展示为平台已合入。
- 当前 `doctor` 结果不冒充历史健康趋势，无快照时不展示问题持续时间。
- 无活动、无数据、读取失败、未登记和样本不足具有可区分的展示。
- Dashboard 不参与门禁判定，不能绕过人工确认和交付授权。

## 二、项目注册与生命周期

- `init`、`install` 能登记或更新项目，注册失败不影响原命令的门禁结果。
- `harness projects add <路径>` 能登记已有仓库，重复添加同一 common dir 不产生重复项目。
- `harness projects list --json` 输出有效 JSON，包含稳定标识、规范化路径、状态和登记时间。
- 注册表并发更新不会丢失其他项目，写入采用原子替换，权限仅允许当前用户读写。
- `uninstall` 标记项目已卸载并保留历史，不删除账本或证据。
- 路径移动、项目删除、权限不足和无效仓库分别显示明确状态。
- 没有可靠身份证据时不自动合并两个项目，移动后的历史关联需要显式重新绑定。
- 最近活动来自账本，不在每次工具调用中为刷新注册表增加额外写入。

## 三、只读采集与历史兼容

- 打开页面、读取账本和生成 JSON 不在项目中创建目录、归属文件、密钥或证据。
- 采集不修改项目配置、账本、签名记录、Git 引用、Worktree 或客户端配置。
- 主分支已有配置时，配置摘要来自主分支固定提交，不使用任务分支配置替代。
- 旧账本缺少事件 ID、schema、项目 ID 和 harness 版本时仍可按既有字段读取。
- 未知事件和未知字段不导致全局失败，并进入覆盖范围或警告。
- 单个项目的账本损坏、权限不足和版本不兼容只降级该项目，其他项目正常返回。
- 历史账本不被重写，聚合结果只存在于内存读模型或明确标记的 Dashboard 自有派生数据中。
- 不为了读取账本调用会生成密钥的接口。
- 签名校验只复用现有校验接口并取得状态，HTTP 路由和前端不直接读取或返回证据密钥内容。

## 四、指标正确性

### 时间与窗口

- 7、30、90 天滚动窗口的起止时间明确，边界事件只归入正确窗口。
- 周趋势沿用 UTC 周一边界并在页面标注。
- 测试注入固定当前时间，覆盖跨日、跨周、跨月和窗口边界。
- 没有样本的时间桶不补成零比率。

### 验证

- 首过率按 `(projectId, tree)` 的完整历史第一次正式验证计算。
- 同一 tree 在窗口前首次验证、窗口内重跑时，不进入该窗口首过率分母。
- 同一 tree 在不同项目中分别计算，跨项目聚合不共用 `seenTrees`。
- 定向验证、探索性操作和缺 tree 的旧事件不进入正式首过率，并说明覆盖影响。
- 跨项目总首过率按总分子除以总分母计算，不对项目百分比取平均。
- 验证总耗时、平均数和中位数与合成事件手工结果一致，缺失耗时不按零解释。

### 评审、交付与策略

- 正式评审拒绝率排除探索性评审和预检拒绝，后两者单独计数。
- 缺失评审成本不当作零成本，成本汇总说明覆盖范围。
- 本地合并、远程请求就绪和同步分别统计，不能相加为完成交付。
- 任务归一化只使用可靠关联的记录，无法关联的记录被计数并说明。
- 不展示缺少完整调用分母的工具调用拦截率。
- 策略拒绝按规则和客户端分布正确，频繁拒绝只生成复核提示，不直接判定配置错误。
- 合并后同步命令失败与待完成合并后验收分别展示。

### 空值与聚合

- 分母为零时 JSON 比率为 `null`，页面显示暂无样本。
- 每个比率能查看分子和分母，跨项目趋势可追溯到项目数据。
- 单项目现有 `metrics` 与跨项目模块对同一账本采用一致定义。
- 如修正现有滚动窗口首过率，新增用例在原实现上能复现错误，修复后 CLI 和 Web 共享用例均通过。

## 五、JSON 与 CLI 契约

- 快照包含 `schemaVersion`、`generatedAt`、`timeRange`、`projects`、`metrics`、`coverage` 和 `warnings`。
- 数据覆盖范围包含登记数、读取成功数、读取失败数、事件时间范围、未知事件数和无法可靠去重的旧事件数。
- 警告包含稳定机器码，页面无需匹配自然语言文本来判断类型。
- `harness metrics --all --days 30 --json` 输出跨项目 JSON，不带 `--all` 的现有文本行为保持兼容。
- `harness doctor --json` 输出当前项目结构化诊断，未指定远程检查时没有远程请求。
- `harness projects list --json` 的错误、空列表和正常输出符合既有 CLI stdout、stderr 与退出码约定。
- Web 与 CLI 对同一输入返回相同指标，不允许网页自行解析文本或复制聚合公式。
- 新 JSON schema 有版本测试，新增可选字段不破坏旧读取器。

## 六、HTTP 与隐私

- 服务默认只监听 `127.0.0.1` 并使用随机端口，不能从非回环地址连接。
- 每次启动生成新的随机访问令牌，缺少或错误令牌的 API 请求被拒绝。
- 非预期 `Host`、跨源 `Origin`、跨域读取和非必要 HTTP 方法被拒绝。
- 快照与详情响应包含 `Cache-Control: no-store`。
- 页面 CSP 不允许第三方资源，运行期间没有外部网络请求、在线模型调用或遥测。
- 静态资源路径穿越、编码后的路径穿越和任意文件路径参数均不能读取项目或用户文件。
- API 只返回白名单字段，不含密钥、token、原始命令输出、报告全文、提示词和会话正文。
- 使用合成凭据、带凭据 URL 和敏感字段测试输出，确保敏感值不进入快照、页面和普通日志。
- 打开页面不运行测试、黄金任务、评审、交付、配置修改或远程查询。
- 页面不存在 `merge`、`submit`、`confirm --yes`、配置保存或其他门禁写操作入口。
- 命令退出后端口关闭且无后台进程残留，重复启动不会要求固定端口。

## 七、页面与分析

- 总览展示项目范围、近期活跃、核心指标、采集时间、数据覆盖和异常项目数。
- 项目比较展示活跃天数、配置背景、版本、交付模式、核心指标及样本数。
- 项目详情展示当前配置来源、健康结果、流程时间线、失败检查和待完成义务。
- 7、30、90 天切换会同时更新页面数据和显示的时间范围。
- 空态、部分项目失败、全部项目失败、无注册项目和大量事件均有可读展示。
- 每条改进提示包含证据、样本范围、不确定性、建议命令和项目链接。
- 建议命令只供复制或查看，点击不执行命令。
- 页面不提供综合健康分，不把绝对事件数解释为项目优劣。
- 常用桌面与移动视口完成浏览器走查，筛选、下钻和错误提示可用，键盘焦点清晰可见。
- Dashboard 静态资源或 HTTP 服务失败不影响现有 CLI 和核心门禁。

## 八、测试层级与真实走查

- 单元测试覆盖指标、时间窗口、事件适配、去重、脱敏和注册表状态转换。
- 集成测试复用 `test/helpers.mjs` 创建多个隔离仓库及共享 Worktree，覆盖安装、登记、卸载、移动和失联。
- CLI 端到端测试覆盖 JSON、文本兼容、退出码、错误输出和单项目与跨项目一致性。
- HTTP 测试通过真实回环端口发请求，不只调用路由函数。
- 浏览器走查验证真实快照加载、时间筛选、项目比较、详情下钻、空态和错误态。
- 安全测试验证令牌、Host、Origin、路径穿越、外部请求和敏感字段过滤。
- 性能测试只在实测出现规模问题后用于评估增量读取或缓存，不以预估数据量作为引入数据库的理由。
- 全量 `npm test`、`npm run docs:check` 和 `git diff --check` 通过。
- 面向用户的命令与行为实现后更新 `docs/reference.md` 和适用的文档站正文，生成差异经过审查。

## 九、阶段门禁

- 阶段一未通过项目去重、只读采集、指标和 JSON 验收时，不进入 Dashboard 页面实施。
- 阶段二未通过本机访问控制、敏感字段过滤和只读验收时，不交付 Web MVP。
- 健康历史只有在存在带时间戳的真实采样快照后才能验收。
- 任务漏斗只有在任务关联键覆盖验证、评审和交付事件后才能验收。
- 常驻服务、定时采样、远程访问和 Web 写操作不属于本清单授权范围。
