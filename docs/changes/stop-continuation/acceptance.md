# 收尾检查续跑与多阶段方案验收

## 范围

多阶段方案的阶段授权与阶段间续跑、收尾提示按进度给下一步、无进展放行可配置并通知用户、规则与托管块补充。
不自动建分支、授权或合并，不解析客户端会话记录与验收清单条目，不出现项目专属名称。

## 阶段授权

- 没有阶段文件时，`approve`、`status` 与收尾检查的行为和输出与当前版本一致。
- `approve --stages` 记录覆盖全部阶段的授权，包含用户原话、阶段文件哈希与各阶段验收清单哈希。
- `approve --stages` 在阶段 `id` 重复、阶段验收清单未提交、建议分支名不符合当前 `branch-name` 规则时拒绝，并说明原因。
- `approve --from-stages` 不接受 `--note`，写入的普通授权记录照搬阶段授权原话并注明来源，现有合并门禁据此通过。
- `approve --from-stages` 在主分支阶段文件已变、新分支验收清单与阶段授权哈希不一致、前序阶段未合入时拒绝。
- 阶段按 `id` 关联分支，阶段分支改用合规的新名字后无需用户重新授权即可记录授权。

## 收尾检查

- 本会话推进过的阶段分支合入后，下一阶段没有分支时，收尾检查给出包含建议分支名、阶段验收清单与 `approve --from-stages` 命令的欠项。
- 下一阶段已有未交付分支时，提示接着完成该分支；全部阶段合入后不再提示。
- 欠项为缺验证或缺评审时，提示写明验收未完成时先继续实现，并要求每一轮以工具调用推进。
- 指纹不变的连续次数不超过 `stop.idleBlocks` 时继续拦截，超过后放行；缺省值为 3，有进展时计数清零。
- `stop.idleBlocks` 非法时回退缺省值，放行提示注明回退，不使收尾检查出错。
- 放行时向用户输出 `systemMessage`，包含分支、欠项、连续次数与恢复方式，账本 `stop.unresolved` 记录连续次数。
- 单个分支的阶段信息读取失败时记录诊断，其他分支照常检查。

## status

- 阶段分支的 `harness status` 显示已合入阶段数、总数与下一阶段；非阶段分支输出不变。

## 规则与文档

- 托管块包含“每一轮以工具调用推进、回应进度提醒后继续调用工具”的要求，现有托管块测试同步更新。
- `assets/rules/harness.md`、`assets/rules/method-design-planning.md` 与文档站说明覆盖阶段文件、两种授权用法、放行通知与 `stop.idleBlocks`。
- 规则、代码与文档不含任何具体项目、阶段或分支名称。
