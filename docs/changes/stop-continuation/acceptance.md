# 收尾检查续跑验收

## 范围

改进收尾检查在多阶段、长任务场景下的续跑与可见性。
不引入项目专属名称，不自动建分支、授权或合并，缺省配置下行为与当前版本一致。

## 验收

- 收尾提示包含“验收未完成时继续实现、每轮以工具调用推进、不要只用文字汇报结束”的通用说明，且不含任何项目专属名称。
- 缺省配置下，指纹不变时放行的时机与当前版本一致。
- 配置 `stop.idleBlocks` 为 N 时，指纹不变的提示最多再出现 N 次后才放行，进展出现后计数清零。
- 无进展放行时，Stop 钩子向用户输出包含分支、欠项和连续次数的 `systemMessage`，账本仍记 `stop.unresolved`。
- `stop.idleBlocks` 取值非法时回退缺省值并给出诊断，不使收尾检查出错。
- 未配置 `stop.stages` 时，收尾检查不读取任何 stages 文件，输出与当前版本一致。
- 配置后，本会话合并的分支属于某份 stages 文件且存在未创建分支的后续阶段时，给出包含阶段名、建议分支名与验收清单路径的提示型欠项。
- 提示不执行任何建分支、`approve` 或合并动作，也不替用户编造授权原话。
- stages 文件格式错误时跳过并记录诊断，不困住会话，其他分支照常检查。
- 全部阶段已有分支或已合并时，不产生提示。
- 完成定向回归、`npm test`、`npm run docs:build`、`npm run docs:check` 与独立评审。
- 不修改版本号与 CHANGELOG，不打标签。
