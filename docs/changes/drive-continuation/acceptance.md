# 无人值守续跑驱动器 harness drive 验收

## 范围

新增 `harness drive`：会话停止后按 harness 的欠项判定自动再开一轮，支持 Claude Code、Codex 与命令模板接入的第三方客户端。
不自动执行需要人完成的动作，不改变既有门禁语义，不配置时不产生任何新行为。

## 循环判定

- 一轮结束后存在 Agent 能接着做的欠项且没有上报阻塞时，drive 自动开下一轮，并把欠项清单与下一步写进该轮提示。
- 没有欠项时停止，原因为完成。
- 只差用户同意实施、门禁改动确认、上报未解除或方案级授权失效时停止，原因为要人处理，并列出具体对象。
- 连续 `maxIdleRounds` 轮进展指纹不变时停止，原因为无进展。
- 连续 `maxFailures` 轮客户端非零退出时停止，原因为连续失败。
- 达到 `maxRounds` 时停止，原因为轮次上限。
- 收到终止信号或被判定为用户接管时停止，并说明原因。

## 会话与可见性

- 默认续跑原会话 ID，终端在 `/resume` 中能看到 drive 写入的每一轮。
- 每轮结束在终端打印一行摘要，含本轮结果、当时欠项与下一轮动作。
- `harness drive --status` 显示会话、轮次、最近一轮时间、欠项与空闲轮数。
- 会话被其他进程占用时拒绝启动并说明；运行中被用户接管时在下一轮前停下。
- `--fork` 基于原会话分叉，原会话不被写入，且分叉会话继承原会话经手的任务分支。

## 客户端通用性

- `claude` 适配器：`-p --resume` 加 JSON 输出，能取回会话 ID 与最终文本。
- `codex` 适配器：`exec resume` 加 JSONL 输出，能取回线程 ID 与最后一条消息。
- 模板适配器：支持 `${session}`、`${prompt}` 占位符与 `json`、`jsonl`、`text` 三种输出解析；用测试里的假客户端证明模板能驱动一个非内置客户端。
- 客户端配置放在本机 `~/.config/harness/drive.json`，不读项目仓库内的版本，避免任务分支改写驱动器行为。

## 安全

- `harness drive` 只能由人启动：Agent 通过工具运行 `harness drive` 被门禁拒绝，并说明理由与正确做法。
- drive 不调用 `harness approve`、`harness confirm`、`harness escalate resolve`，不自动记录任何授权或确认。
- `-p` 模式下 PreToolUse 钩子确实执行，用真实用例或实测记录证明，不靠推断。
- 启动首行打印客户端、会话、权限模式与轮次上限。
- 客户端不支持落盘会话时拒绝启动。

## 通知与记录

- 每轮写 `drive.round`，停止时写 `drive.stop`，内容含会话、轮次、欠项快照与停止原因。
- 配置了 `notify` 命令时，停止时执行一次并正确替换占位符；未配置时不执行任何外部命令。
- `harness status` 增加一行最近一次 drive 的会话、停止原因与时间。

## 兼容性

- 未配置 drive 时，既有命令的输出与行为不变。
- 新增配置项都有缺省值，缺省值与不配置等价。
- 新增门禁规则只匹配 `harness drive`。

## 交付

- 每条行为先有失败用例再实现，记录红灯命令与输出。
- 端到端用假客户端覆盖“中途失败后自动续跑直到完成”。
- `npm test`、`npm run docs:build`、`npm run docs:check` 与 `git diff --check` 通过。
- 完成独立评审，合并本地 `main` 并推送 `origin main`，删除任务分支。
- 不修改版本号与 CHANGELOG，不打标签。
