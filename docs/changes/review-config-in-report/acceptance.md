# 0.19.2 汇报评审配置验收

## 范围

任务完成汇报要写明方案评审与代码评审各自的客户端、模型和 effort，方便用户发现评审配置不合适时及时调整。
代码评审的评审者信息已有记录和展示，只补规则与 merge、submit 日志。
方案评审补 effort、端点和备选标注，并修掉完成行的空模型位。
不改评审门禁、证据记录结构、账本事件和托管块。

## 验收

- `harness.md` 要求交付汇报写一行代码评审的评审者，来源是 `status` 或 merge、submit 日志里的摘要，不自己拼，不省略“由备选完成”。
- `harness.md` 要求方案评审在交出方案时汇报评审者，因为方案评审不写记录，到交付时信息已不在上下文里。
- 规则明确端点域名只写在对用户的汇报里，不进提交说明、PR/MR 描述和 `spec.md`；PR/MR 描述的摘要仍不含域名。
- 方案评审完成行带名称、客户端、模型、effort，由备选完成时注明；codex 没配模型时不再输出空模型位。
- 没配 effort 的新记录显示“effort 客户端默认”，没有 effort 字段的旧记录不显示 effort，不写成客户端默认。
- `harness merge`、`harness submit` 复用已通过的评审时，日志写出评审者摘要。
- 摘要里的 effort 是配置值，文档如实说明不是客户端回报的实际强度。
- 已有的评审、合并、提交、状态输出和既有测试保持通过。
- 完成定向回归、全量 `npm test`、`npm run docs:check` 和独立评审。
