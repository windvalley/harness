# API 失败后的会话续跑验收

## 范围

首版支持 Claude Code 本地 CLI 的中断提示与人工续跑。
自动派发缺省关闭。
自动派发必须通过下文的会话交接验收才能宣布可用。
其他客户端的接入条件见[方案](plan.md#客户端接入状态)。

## 中断与欠项

- 用 Claude Code 2.1.326 和回环假接口证明 API 失败触发 `StopFailure`，事件含原 `session_id`，正常 `Stop` 不触发。
- `stop-failure` 钩子接收 `cwd`、`session_id` 和错误类型，以退出码 0 记录中断。
- 配置缺省关闭、主分支未接入、授权缺失或会话写入权未知时，`status` 显示中断原因和人工恢复提示，续跑启动的 Claude 进程数为 0。
- 欠项计算分别给出完成、仍可推进、等待人工、无法判定。
  用无会话记录、分支读取失败、未获实施授权、存在有效未解除上报和任务已完成的夹具逐一验证。
  只有仍可推进时才启动 Claude。
- 续跑查询前后 `Stop` 的拦截计数、放行记录一致。
  正常前台收尾继续按现有 `stop.idleBlocks` 工作，受控后台调用由其续跑器决定重试。

## 授权与门禁

- 任务分支和主工作树未提交的开关变更对自动派发无效。
  可信主分支已经启用、但新检出的本机尚未授权时，也只提示。
- 受信任的前台展示会话、仓库、任务和交付授权范围、权限模式与预算。
  操作者确认后，授权只对所展示的范围有效，伪造钩子载荷、设置环境变量和模型调用受保护的入口均不能获得或扩大本机授权。
- 即使项目关闭普通门禁改动确认，启用自动续跑和扩大权限、范围或运行上限仍需要人工确认。
- 自动和人工续跑都验证有效门禁，用被拒绝的工具调用夹具证明拦截生效。
  钩子缺失、执行失败或被改写时，工作区写入和其他受保护动作的实际执行次数为 0。
  同样验证运行中撤销授权后无后续模型调用。
- 缺省权限模式为 `dontAsk`。
  测试隔离环境与本机单独授权是启用 `bypassPermissions` 的共同条件。
- 已获方案级授权的下一阶段可用 `approve --from-stages` 接续，超出授权范围时停止。
  技术解除要求仍按现行证据规则验证，`confirm --yes` 与 `escalate answer` 的人工决定由人完成。

## 会话交接与取消

- 人工 `harness continue --session <id>` 在前台确认交接、任务范围和预算。
  通过本地假接口验证用原工作目录和原会话 ID 恢复，提示作为单个参数传入。
  原 TUI 仍在写入或交接情况未知时，引导人在原会话继续。
- 自动派发验收使用实际 Claude Code CLI，覆盖原 TUI 仍打开但空闲、退避期间用户恢复和后台运行时用户接管。
  每个场景在同一时刻只允许一方写入会话，无法核实交接时只留提示。
  使用并发 `--resume` 的两个进程验证该条件，进程扫描结果不足以替代断言。
- 对同一会话并发触发，只产生一个已授权的后台运行。
  对同一 Worktree 的不同会话并发写入，仅一个续跑器取得写入权。
- 子客户端触发 `StopFailure` 时，失败进入本次运行记录，派发次数保持一次。
  重复事件或续跑器重启后，次数、时限、预算和停止结果从已登记记录恢复。
- 分别用 `harness continue cancel --session <id>` 和前台 Ctrl-C 验证退避与执行期间的取消。
  原有进程完全停止后释放锁，记录取消或接管原因。
  异常退出仅在确认原进程及其客户端已经结束时回收锁。
- 交接验收通过后，用假客户端覆盖一次 `unknown` 中断后继续到完成，并保留真实 CLI 的交接测例。
  交接验收未通过时，以提示和人工恢复的交付范围验收。

## 重试与运行上限

- HTTP 429、500 与 529 进入退避可重试路径，529 按实际 `server_error` 载荷处理。
  等待时间按轮次增长并受上限约束，可用虚拟时钟验证。
- 同一次运行最多因 `unknown` 重试一次，输出截断使用简短的续跑提示。
  鉴权、计费、账号或请求配置错误在首次失败后即等待人处理。
  `skipErrors` 命中时只记录跳过原因。
- 结果解析以退出状态、`is_error` 和规范化失败事件为准。
  用 `subtype: "success"` 且 `is_error: true` 的夹具证明该轮记为失败。
- 分别验证达到无头调用数、连续失败数、同错且无进展次数和无进展轮数上限时记录对应原因。
  失败与同错计数均从触发续跑的原失败开始。
- 用真实 CLI 验证一次调用内可产生多次模型请求，并验证客户端轮次和预算参数已生效。
  用 `error_max_turns` 验证按欠项决定是否进入下一轮，用 `error_max_budget_usd` 验证整次运行停止。
  用挂起的假客户端验证每轮和整次运行超时后停止进程树、释放锁，退避时间计入整次运行。
- 用假客户端验证按每轮增量花费扣减总预算。
  预算缺失、耗尽、无法核计费用或将调用无法纳入预算的付费步骤时停止自动执行。

## 日志与交付

- `status` 显示关联分支、会话、调用次数、等待期间的下次尝试时间和停止原因，可定位本机日志。
  未关联任务分支时，从主分支的 `status` 也能定位该会话的提示。
  日志通过共享 Git 数据目录存取，在主工作树和 Linked Worktree 均可读取。
  验证日志文件权限、体积和过期清理。
- 用合成敏感值验证原始 stdout、stderr、错误详情及工具结果不会进入状态、日志、账本或通知。
  默认运行只产生必要的结构化字段。
- 恢复原会话时可看到简短续跑提示。
  配置了本机 `notify` 时，启动和停止各通知一次，摘要按参数传入。
  默认仅凭 `status` 和本机记录即可核对进度。
- 安装、诊断和卸载覆盖 `StopFailure`，验证用户已有钩子及旧版正常 `Stop` 行为。
- 各关键行为保留失败用例与实现后的通过记录，试验使用隔离夹具和回环假接口。
  `npm test`、`npm run docs:build`、`npm run docs:check` 与 `git diff --check` 通过后完成独立评审。
  交付说明写明已验证的版本、功能范围与自动派发验收结果。
