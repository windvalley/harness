架构总览

三层防线

一次改动从 Agent 调用工具开始，到写进主分支为止，要依次经过三层检查。前两层在过程中纠正，第三层在结果上把关。

层何时生效管什么覆盖谁
① 实时拦截支持并已启用的客户端钩子调用工具之前读取密钥、改写门禁入口、不可逆的 git 操作、绕过开关正确接入钩子的客户端；通用入口仅提供拦截，没有收尾检查
② git 钩子本机钩子安装并生效时的提交与引用更新提交信息、暂存的密钥文件、主分支的写入经过本机 git 钩子的客户端和人
③ 受控交付通过 harness merge 或 harness submit 交付时验证证据、独立评审、实施授权、门禁改动与交付设置变化的人工确认使用 harness 交付命令的任务

即使某个客户端没有接上实时拦截（例如 Codex 还没信任钩子），已安装且生效的 git 钩子仍会检查提交与本地主分支更新；使用 harness merge 或 harness submit 时，还必须满足验证、评审与相应授权条件。平台最终合入的内容由 GitHub/GitLab 的保护规则把关，harness 不防有意绕过本机机制的进程。

实时拦截：一次工具调用怎么被判定

以 Claude Code 为例，客户端配置里的 PreToolUse 钩子在每次读、写、执行命令之前运行入口脚本。其他客户端的判定相同，只是载荷格式与拒绝的返回方式由各自的适配器处理。

判定依据是这次调用的路径、命令和写入内容，对照主分支上 policy.json 的规则。命令写文件时，引擎会解析重定向、sed -i、tee 等写入目标，目标无法静态确定时，在受保护的目录里按最严格处理。实时拦截是安全边界，宁可误拦，也不放过无法判定的调用。

收尾检查：Agent 想结束时

三层门禁也不能保证 Agent 会在结束回复前完成任务。为此支持的客户端钩子还挂了一道收尾检查：Agent 每次结束回复前，核对本会话推进过的任务是否已经交付；没有交付又没有上报阻塞时，告诉它还差哪几步，让它接着做。只差你确认门禁改动或同意方案时放行，两次结束之间没有任何进展时也放行，但会记下来，在 harness status 里给你看。

收尾检查与实时拦截的失败策略相反：实时拦截是安全边界，出错按拒绝处理；收尾检查是流程提醒，出错时放行并只提示一行，免得门禁自己的问题把会话卡住。Claude Code 对所有阻止结束的 Stop 钩子都显示 Stop hook error occurred，原因在随后的反馈里，不是门禁出错。

git 钩子：提交与主分支更新怎么被判定

git 钩子对所有客户端和人都生效，是实时拦截没接上时的兜底。安装时 harness 把检查块插在钩子脚本的最前面：已有的脚本常见写法是“没有相关改动就 exit 0”，追加在末尾的块会跑不到。

pre-commit 先判这次提交本身能不能发生，例如主 Worktree 只用来合并，不接受提交；再对暂存区的每个路径跑写保护规则，对新增的行扫内容禁止规则。layer=agent 的规则只约束 Agent 的实时调用，git 层看不出写入者，所以跳过。commit-msg 先按 git 默认的规则清理注释行、剪刀线和行尾空白，再按提交信息规范判定；合并提交只是同步分支，与合并时的口径一致，放行。

reference-transaction 在每次更新引用时触发，只对 main 与 master 求值。update-ref 不带旧值时钩子收到全零，必须以引用当前的实际值为准，否则零值会成为绕过口。令牌的生成与比对见主分支只认合并令牌。

组件与数据放在哪

项目里只入库配置和一个很小的入口脚本，门禁代码、密钥和运行记录都留在本机。

位置内容入库
.harness/config.json、policy.json、verify.json项目参数、拦截规则、检查映射是
.harness/golden/tasks.json对规则本身的回归用例（黄金任务）是
.harness/rules/、.harness/templates/给 Agent 读的研发规范与模板，升级时整份重写是
.harness/bin/harness、.harness/VERSION入口与锁定的版本号是
.claude/settings.json、.codex/hooks.json客户端的实时拦截配置是
AGENTS.md 托管块Agent 每次都会加载的硬性要求是
.git/hooks/pre-commit、commit-msg、reference-transaction默认否
.git/harness/证据、评审、确认、授权记录与账本，所有 Worktree 共用否
~/.local/share/harness/按版本安装的门禁代码与签名密钥否
~/.cache/harness/checkouts/verify 的固定检出否
