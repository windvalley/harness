# 设计与任务拆分

复杂功能、接口调整或迁移时使用；通用约束见 [core](core.md)。

- 涉及多模块契约、分步依赖或迁移的需求，实现前分别记录行为说明与实施方案。已有文档直接复用；新建时沿用项目目录约定，无约定则放在 `docs/changes/<change-id>/`。
- 可裁剪使用[行为说明模板](../templates/spec.md)和[实施方案模板](../templates/plan.md)，不新增审批节点。执行结果写入已有任务记录，没有时记在实施方案末尾。
- 以调用者负担和已有架构约束判断接口；不为想象中的扩展引入抽象，不把设计建议变成未经授权的重构。
- 按可验收行为纵向拆分，注明验收、真实阻塞关系和验证入口。
- 跨模块迁移按兼容新增、分批迁移、删除旧实现推进；每批保持必要验证通过，共同集成前不宣称整体可交付。
- 本方法不自动授权多 Agent 委派。已授权并行时明确责任与隔离边界，合并后仍须验证整体行为。
