# 跨平台兼容

产品声明多平台支持，且改动涉及路径、进程、Shell、权限、编码、换行符、大小写、原生模块或平台 API 时使用。
本方法只补充支持范围与验证证据，不新增门禁类型或默认支持范围。

## 支持矩阵

- 按产品契约、已有支持矩阵和项目证据确定目标平台，不默认支持全部操作系统。
  范围仍未明确时标为 `not_evaluated`，不以开发机结果代替未知范围。
- 用 [平台验证矩阵](../templates/platform-matrix.md) 记录 OS、版本或架构、受影响行为、失败语义、测试入口、运行环境、提交与证据。
  小任务可将适用字段写进验收清单，复杂或跨会话任务再维护独立矩阵。
- 使用标准跨平台 API 或明确的平台分支，测试覆盖适用分支、错误语义与边界，不写死本机路径，不用 skip 回避目标平台。

## 验证证据

- 模拟分支测试证明逻辑覆盖，真实平台测试证明运行环境，模拟与真实结果不能互替。
  每项结果标明属于模拟还是真实环境，不用一次本机成功外推全部平台。
- 缺目标 Runner 或真实环境时记录阻塞、影响和补验计划；目标平台的必需验证未运行或失败时，不宣称该平台已通过或可发布。
- 真实 OS 安装、协议注册、权限、签名及原生能力使用最终交付形态验证，替换被测对象的夹具不证明真实性。
- 自动检查沿用项目 `verify.json`，外部平台证据通过 `attest` 登记；只有依赖目标分支集成状态的检查才进入 `post-merge`。
